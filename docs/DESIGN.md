# 状态机设计

源文件按职责划分，入口、依赖方向和旧名称映射见[策略代码导航](CODEMAP.md)。

本版是基于原模拟器的策略扩展。采购评分、阶段切换、预演权重都是可调整的启发式；战斗、叠层触发、价格、卡池和伤害由安装的宿主决定，不在本包另写规则替代。

## 协同入口

`routes.js` 在原生策略选择前集中分配路线。最多四个席位与四条主路线进行不重复匹配，比较实际未被禁用的可见本家干员、静态停用、已持有组件；不为路线分配消耗游戏随机数，分配后固定。它只避免主路线重复，辅助组件仍共享卡池。

策略选择依次尝试路线优先策略、未占用的经济/招募策略和其他可用策略。实际 `bandId`、原生计数和当前库存是策略特性是否可用的依据，不能把首选策略未选中时仍当作已生效。

## 一轮整备

1. 读取当前确认状态，固定本家承诺，识别经济组件、关键干员与当前缺口。
2. 处理待选奖励、可用装备和临时溢出；腾出空间时先恢复本轮要用的干员，再比较可出售的过渡牌。保护核心组件和激活投资人所需成员。
3. 比较当前可买目标、升级收益、刷新机会、当轮折扣和可循环获取收益。刷新留到更高商店等级仅为选择；回合结束会损失的金币需要收尾，不能仅因手牌满而长期停购。
4. 从当前已获取组件构造阵容与站位候选，考虑怪物路径、覆盖、治疗可达、朝向、关系叠层、灵巧范围及部署仇恨顺序。有限预演比较生存、输出和可获得层数。
5. Boss 回合使用对应路线的阵型修正。普通战斗层数不能代替 Boss 输出判断，也不能假定第14、15轮仍可通过战斗触发叠层。
6. 处理可用余款和剩余空间，完成最终部署并准备。

2026-10-26修复：腾位成功不等于真实手牌出现空位，原生重算可能立即把临时牌补入。萨尔贡在部署、使用装备或出售非关键牌后均重新读取确认状态；领取待选奖励只在当前手牌确有空间时执行。主采购的动作上限不终止整备收尾，待选奖励、临时牌及阵容恢复会有界重查。无法安全处理时保留明确的阻塞状态，不通过强制就绪、丢核心或改原生容量掩盖问题。历史撤下的备选核心继续受到出售保护，就绪仅要求当前选定阵容恢复。详见[修复说明](READY-HOTFIX.md)。

谢拉格和萨尔贡由独立状态机执行；拉特兰与叙拉古保留供应商的阶段决策和模拟搜索，并叠加经济收尾及对应修正。关键代码集中于 `policies/`、`support/` 和 `vendor/`。完整来源及修改说明见根目录清单。

## 执行与隔离

Worker 保存当前对局的内存镜像进行思考，预演使用分离状态。真实操作必须返回主线程，由宿主原生处理器确认，随后用确认状态刷新镜像。不会将未来商店预先展开为一串真实操作。

主线程只接受列明的队友整备操作，并检查该席位确为协同 AI、仍存活、仍在同一整备轮次且尚未准备。时限结束、比赛结束、销毁或新任务会取消旧任务。取消先唤醒等待中的请求，给 Worker 正常退出机会，再对未结束任务设置终止兜底。

操作间隔按实际提交的动作计算，范围0–5000毫秒；修改滑块会重排尚未执行的下一步。随机采购由原生规则在主线程执行；AI 评分所需的共享 bot 随机数也从原线程取得，预演可使用隔离克隆。服务器不会把客户端发来的任意方法名转成可执行调用。

本包没有真人席位的定制托管入口，也不包含录制、回放保存、个人轨迹读取或在线训练。公开测试通过原生观战席观察四个真实 AI 席位。

## 可选禁位筛选

四AI观战与禁位筛选分别设置。原生房间默认关闭筛选，四AI模式也不会自行打开。浏览器只记忆用户选中的盟约列表，服务器保存该房间的启用状态；关闭时保留列表，开始前再次核验当前规则是否仍有足够的本家和辅助盟约可抽入禁位。非法或静态停用的候选不能用于放宽校验。

筛选仅把选中盟约从原生抽样候选中排除，再调用原有抽取函数；原禁位数量、禁用后干员判定和随机数处理沿用宿主。默认十盟约条件下保留固定评估器的抽样结果。程序化评估器使用的旧 `routeAITest` 参数保留兼容回退；实际房间总是显式传入筛选开关，所以关闭时不会被该回退意外启用。

## 边界

普通禁位仍可能使一路构筑不完整。有限预演不能枚举全部局面，经济组件与队友资源需求也可能冲突。策略基于本模拟器的数据和接口，局部回归通过不等于官方规则完全一致，固定十局表现也不等于任意开局胜率。
