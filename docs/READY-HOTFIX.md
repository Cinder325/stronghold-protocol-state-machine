# 2026-10-26：v0.1.0 萨尔贡准备就绪修复

版本号保留0.1.0，通过独立修复提交更新现有发布。修复前代码仍可通过提交 `c2166236a3f8ed2a3fa78f933a4dab8dd5ee8c57` 查看。

## 原因与修正

在原版0.3.3、Node.js22、四AI终极模拟的种子111013中复现第15轮萨尔贡未就绪。其余三路已经就绪；萨尔贡实际完成布阵，没有待恢复成员，但一项三合一奖励仍未领取。

原状态机把“成功出售一张非关键牌”当作腾位成功。原生重算会自动把临时区的牌补入刚空出的手牌格，因此领奖仍可能返回 `HAND_FULL`。主采购随后停止；末尾现金收尾虽腾出空间，却没有重试奖励，导致完成状态保留 `blocked`。这不是战斗引擎或供应商策略错误，也不是金币不足应当提前返回的问题。

种子111018在第14轮暴露另一条路径：满战场、满手牌时，新近战核心要替换高台过渡干员，原生地形规则使它们不能直接交换，必须先腾一个真实手牌格。旧逻辑又因核心尚未归位而禁止所有容量清理，形成循环。现在仍保护当前阵容、核心和投资人，只释放允许出售的无关备选，重新布阵并复核收尾。对保存的真实出错状态回放后，核心成功部署、就绪成功且余款为0。

修复始终通过原生操作：先恢复可部署成员、合理使用已有装备，仅在保护规则允许时出售非关键备选，并在每次操作后重新读取实际容量；不会因为出售成功就盲目领奖。达到主采购上限后的末尾仍有界处理待选、临时牌与新阵容，确认安全后发送原生 `g.ready`。

同时修复一个独立可构造的相关问题：较早阵容临时撤下的核心，如果后续候选阵容决定让其留后台，历史恢复标记可能仍把它当作额外必须上场的成员。现在只以当前选定阵容判定恢复完成，旧核心仍在出售保护集合中。仍属于当前阵容、尚未返回战场的成员继续阻止就绪。

没有按特定种子分支，不改卡池、金币、手牌/临时区容量、战斗规则或原生就绪校验，不强制出售核心。供应商原始策略、许可证及固定来源不变；两项本地策略载荷的日期与哈希更新在 `provenance.json` 和安装清单中。

## 复现与检查

使用兼容的干净宿主独立副本，按README安装本次清单。两个原版分别运行：

```sh
node scripts/verify-host.mjs --host ../Stronghold-Protocol
node scripts/benchmark.mjs --host ../Stronghold-Protocol --out ../ready-regression.json --seeds 111013,111018
```

输出文件须尚不存在。检查完整结束、全部存活席位每轮都能就绪、Match/模拟/元效果/调度/原生审计错误为0。战斗胜负仍按原生结算记录；这两个针对性种子不能用来估计一般通关率。

评估器现在在整备失败时立即输出不含私人状态的 `prep-blocked` 摘要（轮次、路线、未恢复成员/临时牌数量和待选状态），并在该轮检查比赛错误，不再等到对局结束才汇总报错。检查标准没有放宽。

新增原生回归覆盖：卖牌后临时牌确实自动补入手牌、主采购动作上限为1和0时仍安全领完奖励并就绪、满手满场的跨地形替换可通过受保护缓冲完成、核心不被出售；阵容守卫回归覆盖旧核心保留与当前成员缺席继续阻塞。CI在原版0.3.1和0.3.3上另跑报告中的两局完整回归。核验结果另存于 `benchmarks/ready-regression-20261026.json`。

## 已安装用户如何更新

先退出游戏并停止宿主服务。下载本次修复包，在新包中先执行卸载的dry-run，再卸载旧修订，然后执行安装的dry-run及安装，正常重启服务。新包卸载器使用宿主内原有恢复记录和旧文件哈希，不要求保留旧扩展文件夹；同版本跨修订卸载/重装已有事务回归覆盖。命令见README，路径参数由用户选择。

安装器以清单摘要区分同版本的不同修订，不能把新包直接覆盖安装到旧修订上。若出现本地修改冲突，检查差异后合并，不删除安装恢复信息或绕过哈希校验。本次不包含个人托管、录制、回放、训练资料或游戏素材。
