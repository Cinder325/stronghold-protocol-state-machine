# 复现说明

使用原始模拟器的固定正式版本，新建独立副本；本包不要求任何私人素材或训练文件。

## 环境与安装

1. 安装 Node.js 22 或更新版本，按原模拟器说明准备完整可运行的宿主。
2. 原版0.3.1固定提交为 `b3deebdae4a92642c007d217a1a4573e5d3612c5`；0.3.3为 `f07b8965061bbc311ad7aa815879b09264a1e47d`。
3. 关闭宿主服务器，在扩展目录执行 README 的 dry-run、安装命令。若源文件哈希不匹配，保留原文件并检查版本或其他插件；不要强制覆盖。
4. 重启原服务器。房间添加队友可选协同或原有 AI；四AI测试要求房主为唯一真人。原版已提供观战切换。“指定盟约不被禁用”默认关闭，首次开启预选四路线所需十盟约；只记忆勾选项，新房间不会自动启用。

通过原始源码准备宿主时，运行其正常 `npm ci` 流程以生成浏览器依赖。仅测试服务端时可以遵循 CI 的 `npm ci --ignore-scripts`，但此方式不能据此宣称浏览器已可运行。

无需Git的使用者可从README的固定源码包链接准备同一基线，再用 `install.cmd` 或 `node scripts/setup.mjs` 选择文件夹。引导入口只调用同一安装器的dry-run与正式执行；不自动检出提交、下载依赖或绕过校验。代码职责和旧文件名映射见[CODEMAP.md](CODEMAP.md)。

## 单元、宿主和界面

```sh
npm test
node scripts/verify-host.mjs --host ../Stronghold-Protocol
```

`verify-host` 安装后，在真实原生第一轮状态上启动四个 Worker，检查均能部署并准备、路线不重复、非AI目标被拒绝和错误数为零。它直接进入第一轮整备，不是完整通关测试。

完整宿主集成测试使用环境变量 `SP_HOST_ROOT` 指向已安装扩展的原版测试副本。可选 `SP_UPSTREAM_ROOT` 指向未安装的原始副本以核对唯一补丁锚点。

2026-10-26准备就绪修复的两个报告种子、原生溢出/奖励回归和同版本更新步骤见[修复说明](READY-HOTFIX.md)。CI分别在两个受支持宿主上检查完整回归对局，不把针对性种子的胜负并入历史十局统计。

PowerShell 示例：

```powershell
$env:SP_HOST_ROOT = '../Stronghold-Protocol'
node --test test/*.test.mjs
```

测试覆盖真实 WebSocket 的选择器协议、默认协同/原有AI、四AI观战、速度修改及座位恢复；战斗模拟另由 benchmark 运行。界面审查应检查进入房间、切换队友类型、测试模式、原生观察对象切换和速度滑块，并检查页面/服务器错误。禁位设置还需核验默认关闭、十盟约初选、更改后关闭再开、刷新及新房间恢复记忆、非法组合拒绝、非房主和开战后禁止修改。安装器还测试拒绝未知源文件、事务失败回滚、重复安装及卸载保留无关数据。

## 固定十局

```sh
node scripts/benchmark.mjs --host ../Stronghold-Protocol --out ./benchmarks/local-run.json
```

默认种子为111001到111010。必须使用尚不存在的输出文件，不能覆盖既有结果。脚本在首局前记录全部种子、实际宿主版本/固定提交、安装清单摘要、评估脚本摘要和宿主源码摘要；每局结束写入简明统计，完整结束标记为 `complete: true`。

统计使用原生最高难度 `ABYSS`、四席共享卡池、真实战斗引擎与完整内容，固定开启四路线默认十盟约的合法禁位筛选。没有额外资源、敌方削弱、强制全员存活或跳过失败局。每一局都校验 Match、模拟、元效果、调度错误和原生规则审计，并检查前后源码摘要一致。

预演权重和状态机运行在同步虚拟调度下，真实操作延时不属于该基准。十局是固定条件下的策略验证，不应宣传成未筛选禁位、真人混合房间或任意 Worker 速度的胜率。原版0.3.1与0.3.3的规则修复不同，跨版本结果也应分别统计。

结果包含逐局地图、Boss、禁位、淘汰与第14/15轮信息，以及每条路线、每个原生盟约的层数。清场均值只使用对应团队通关且路线入场仍存活的样本，并列出样本数。第15轮未进入与进入后失败分别保留。

公开的十局及单局真实Worker证据保留追加禁位设置前的安装清单摘要；发行清单因此与历史结果不同。`benchmarks/release-equivalence.json` 记录差异范围、未变的策略载荷摘要及两版各266种子的原生抽取比对。重新运行评估器会记录当前发行清单摘要，不应手工改写历史结果哈希。该设置追加未重跑完整十局，兼容性与记忆功能另用两版实际浏览器核验。

## 发布复核

```sh
node scripts/audit-release.mjs

```

审计拒绝发布树中的私人路径、邮箱、令牌、设备标识、依赖目录、媒体和大体积文件等；额外私人词表只能放在发布树之外。还需人工审阅来源、提交作者身份、实际暂存文件及文档链接。自动扫描通过不能替代人工审查。源文件和安装载荷的摘要分别见 `provenance.json` 与 `addon-manifest.json`。
