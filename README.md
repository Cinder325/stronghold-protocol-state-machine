# 卫戍协议四路线协同 AI

**v0.1.0 · 非官方、非商业的队友 AI 扩展。** 为 [Stronghold-Protocol](https://github.com/sganggs/Stronghold-Protocol) 的「卫戍协议：盟约」增加一个“协同四路线AI”选项。最多四个实例分别经营拉特兰、谢拉格、萨尔贡、叙拉古，避免重复主路线。使用状态机和有限模拟搜索，不包含神经网络权重。

本包只提供队友策略、接入补丁、测试模式及复现工具，不包含游戏本体、美术、声音、存档、个人操作轨迹或录制功能。头像引用宿主已有的塑心素材标识。首次版本仍有局限，欢迎通过 Issues 提交可复现问题。

## 安装与卸载

需要 **Node.js 22 或更新版本**。先按[原模拟器说明](https://github.com/sganggs/Stronghold-Protocol#readme)完成可运行的游戏安装。本扩展没有额外 npm 依赖。

以下命令在本扩展目录运行，假设游戏位于相邻的 `Stronghold-Protocol` 文件夹；也可将参数换成实际目录。**安装、卸载前先关闭游戏服务器。**

```sh
node scripts/install.mjs --target ../Stronghold-Protocol --dry-run
node scripts/install.mjs --target ../Stronghold-Protocol
```

然后照常启动原版游戏并刷新浏览器。源码安装宿主需要运行其 `npm ci`；如果此前跳过了 postinstall，需按原版说明补齐浏览器 vendor 依赖，不能只准备服务端依赖。

卸载会恢复本扩展实际修改过的原文件，移除本扩展新增文件：

```sh
node scripts/uninstall.mjs --target ../Stronghold-Protocol --dry-run
node scripts/uninstall.mjs --target ../Stronghold-Protocol
```

安装器在宿主 `.stronghold-state-machine-install/` 保存最小恢复信息，不处理用户数据和素材。重复安装同一版本不会重复打补丁。若安装后手工修改了扩展拥有的文件，卸载会拒绝覆盖这些修改；请先检查冲突。升级扩展前卸载旧版本。

## 使用

同盟房间的“添加队友类型”默认选中**协同四路线AI**，也可选原有AI。多个协同实例依座位编号为 1、2、3、4。路线在选策略前统一分配并固定；比较实际可获取的本家干员、禁位和静态停用条件，主路线不重复。共用的辅助干员和装备仍可能竞争，不能保证完全不抢牌。

| 主路线 | 优先策略 | 主要规划 |
| --- | --- | --- |
| 拉特兰 | 潘格尼尼 | 经济、重复获取收益、充能与输出覆盖，Boss 阵型修正 |
| 谢拉格 | 休露丝 | 当轮首张折扣、本家与投资人保护、冻结覆盖、灵巧/奥术关系叠层 |
| 萨尔贡 | 佩佩 | 本家经营、转职/叠层组件、可用特殊刷新、现金收尾 |
| 叙拉古 | 贾维 | 获取与升阶循环、经济组件、Boss 覆盖和支援 |

如果优先策略已被别人选走，先尝试梓兰、杰西卡等有经济或招募收益的可用策略，再尝试其他未占用策略。不会因为路线名而虚构原策略特性：例如只有实际选择佩佩且原生计数存在时，才考虑保留其特殊刷新；只有休露丝实际生效时才按首张折扣决策。

未开启禁位筛选时保持原始禁位抽取。若四个实例同时参加而禁位限制了某一路线，本版会保留互不重复的路线并使用实际仍可用的组件降级经营；不保证这种开局具有完整构筑强度。

## 四 AI 测试模式

房主为唯一真人时，可以在房间勾选“四AI终极模拟测试”。开始后房主进入**原生观战席**，四个游戏席位全部由协同AI控制；使用原版队友栏切换观察对象，Boss 回合沿用原版配对和两侧场地。结束或启动失败后恢复原房间座位，不替换其他真人。

房间另有“指定盟约不被禁用”设置，**默认关闭**，与四AI测试模式独立。首次打开时默认勾选四条路线需要的以下盟约，可自行调整：

- 本家：拉特兰、谢拉格、萨尔贡、叙拉古。
- 辅助：灵巧、精准、迅捷、奥术、远见、奇迹。

勾选项保存在当前浏览器，关闭功能、刷新页面或重新进入房间都不会清空；新房间仍默认关闭，打开后恢复上次选择。此设置不上传浏览器标识或个人信息。清理浏览器站点数据会重置记忆。

开启时是**原禁位分布在所选条件下的抽样**，仍保留原有本家/辅助禁位数量。服务器校验可选盟约及剩余候选数量，拒绝全选等无法产生合法禁位的组合；设置错误不会静默改变禁位规则。关闭时即使开启四AI测试，也使用原始随机禁位。因此筛选后的通关统计不能直接代表随机普通开局。

房间和战斗中的滑块可调整 **每步 0–5 秒**。每次实际采购、移动、装备等操作后按设定等待，并读取宿主确认状态后再决策；计算和模拟搜索也需要时间。滑块不改变战斗倍速或原生回合期限，较慢的操作可能来不及完成整备。

这里评估的是**策略**：使用原版虚拟时钟、原生座位延时、同步运行同一套状态机和真实战斗引擎。游戏内实际接入使用 Worker，不同操作速度及并发时序可能改变共享卡池的获取顺序；这十局不是各速度下的端到端胜率，也不是性能基准。另行验证的真实 Worker、WebSocket 和浏览器接入用于检查可用性。

**结果对应版本：**十局及下述 Worker 整局完成后，追加了可调整、可记忆的禁位设置，未重新跑十局。原始测试哈希保持不变；213 个策略、执行及供应商载荷逐字节未变，新增设置只涉及房间、浏览器和禁位筛选入口。两版各用 266 个种子核验默认十盟约的禁位、禁用干员和 RNG 状态与测试时一致，关闭时与原生抽取一致。[设置扩展核验记录](benchmarks/release-equivalence.json)区分测试清单和发行清单，不能把它视为新一轮端到端通关统计。

另测最终版真实四Worker整局（开发种子111000、原版0.3.3）：**第14、15轮均通关**，运行与规则审计错误均为0，萨尔贡1–15轮准备时余款均为0。[简明功能验证结果](benchmarks/worker-functional-111000.json)保留了各轮余款和结算核验。此验证等待Worker时暂停了虚拟整备时钟，不计入十局通关统计，也不证明实时性能。较早候选的同种子Worker局曾在第14轮战败；并发顺序和构筑不同，不能据此计算修复前后的配对胜率。

**萨尔贡资金修正：**为此前发现的13金币未用问题补充整备收尾，处理采购循环因容量或搜索上限结束后的可用预算，优先使用道具、释放安全空间并采购有用目标。原生受控回归覆盖“13金币＋满手牌”，确认实际装备/叠层收益且核心与三投资人不丢失；满手不能直接购买装备的原规则保持不变。仅在有明确可买目标且没有安全使用对象时，才清理阻塞采购的无用信标；转职、罗盘、投影等核心物品保留。确无安全合法操作时会记录保留原因，不通过卖核心强行清零。其它路线或构筑仍可能有保守冻结、站位或资源利用不足的问题。

第14轮通关以原生 Boss 池清空为准；第15轮同时报告全部十局和实际进入该轮的分母。层数均为该轮**团队通关且该路线在该战斗入场时仍存活**的样本均值，保留零层、未激活盟约及样本数；不能把未进入或已淘汰的路线当成零层样本。
